# Наше потом — карта желаний

Небольшой сайт для общих планов: идеи, даты, отметки о сбывшемся и фотографии. Python backend поддерживает локальную SQLite и Supabase. Голосовые напоминания можно распознавать через Supabase Edge Function с Gemini; локальный `faster-whisper` остаётся автоматическим запасным вариантом.

## Запуск в Windows

Нужен Python 3.10 или новее. Откройте PowerShell в папке проекта:

Диапазон PyAV ограничен версией ниже 19: более новый PyAV несовместим с аргументом `metadata_errors`, который faster-whisper использует для чтения голосовых Telegram.

```powershell
python -m pip install -r requirements.txt
python app.py
```

Откройте <http://127.0.0.1:8765>. Порт можно изменить переменной `PORT`. Данные сохраняются локально в `data/wishlist.sqlite3`. Для резервной копии достаточно сохранить этот файл.

## Подключение Supabase

Локальная SQLite остаётся резервной копией. Пока переменные Supabase не заданы, сайт продолжает работать на SQLite.

1. В Supabase откройте **SQL Editor → New query**, скопируйте содержимое `supabase/schema.sql` и нажмите **Run**.
2. Откройте **Project Settings → API Keys**. Скопируйте **Secret key** (`sb_secret_...`) и Project URL. Это ключ полного доступа к базе: храните его только в PowerShell на компьютере с Python backend. Не вставляйте его в JavaScript, HTML, SQL Editor, Git или чат. Старый JWT `service_role` поддерживается для совместимости, но предпочтителен новый Secret key.
3. В PowerShell, из папки проекта, задайте адрес. Скопируйте **Secret key** кнопкой копирования в Supabase, затем прочитайте его прямо из буфера обмена. Так PowerShell не потеряет символы при вставке в защищённый `Read-Host`:

   ```powershell
   $env:SUPABASE_URL = Read-Host "Project URL"
   $env:SUPABASE_SECRET_KEY = (Get-Clipboard -Raw).Trim()
   if ($env:SUPABASE_SECRET_KEY.Length -lt 20) { throw "В буфере обмена не найден полный Secret key. Скопируйте ключ в Supabase и повторите." }
   "Secret key загружен из буфера обмена."
   ```

4. Сначала проверьте доступ и реальную запись: скрипт создаёт временное желание в Supabase, читает его обратно и удаляет:

   ```powershell
   python scripts\check_supabase.py
   ```

   В конце должно появиться `Тестовая идея создана, прочитана и удалена; запись в Supabase подтверждена.`

5. Перенесите текущие настройки и желания (повторный запуск обновляет строки с совпадающими ID):

   ```powershell
   python scripts\migrate_to_supabase.py
   ```

   Скрипт не удаляет данные из Supabase или локальной SQLite. Фото хранятся в таблице как data URL; для крупного объёма фото позднее лучше перейти на Supabase Storage.
6. В том же окне запустите или перезапустите сайт:

   ```powershell
   python app.py
   ```

   При запуске сервер использует Supabase, если заданы обе переменные. Удаление желания отправляет `DELETE` в Supabase, а API подтверждает удаление перед обновлением списка.

Если Supabase ещё не подключён, запуск `python app.py` без этих переменных продолжит использовать SQLite. Не удаляйте локальный `data\wishlist.sqlite3`, пока не проверите перенесённые данные.

## Бесплатная публикация на GitHub Pages

GitHub Pages размещает только файлы интерфейса (HTML, CSS и JavaScript), а не запускает Python. В этом варианте браузер обращается к Supabase напрямую: Supabase Auth проверяет вход, а политики RLS ограничивают доступ к общему списку двумя добавленными участниками. Код страницы будет виден посетителям; приватность данных обеспечивается Supabase, не секретностью сайта или репозитория.

Локальный запуск `python app.py` и SQLite остаются без изменений. Pages-сборка исключает старые Python API-клиенты, но включает `static/photo1.jpg` как фото на главной; остальные личные фото в GitHub не добавляются, а фотографии альбома хранятся в приватном Supabase Storage. Telegram-бот и уведомление при выполнении остаются на стороне Supabase. Не помещай в сайт или GitHub `SUPABASE_SECRET_KEY`, `service_role`, Telegram-токены, пароли, локальную SQLite-базу и личные фото.

### Настройка Supabase

1. Создай два пользователя в **Authentication → Users** с личными email и паролями. Публичную регистрацию отключи: пользователей следует создавать вручную.
2. Открой **SQL Editor**, выполни по очереди [миграцию доступа Pages](./supabase/pages_access.sql) и [настройку воспоминаний, историй и приватного фото-хранилища](./supabase/memories_access.sql). Если таблица воспоминаний уже существует, повторный запуск второго файла добавит новые поля превью и увеличит лимит оригинала до 20 МБ; миграция также безопасно переносит прежние рассказы к фото.
3. В SQL Editor выполни запрос, заменив адреса на email этих двух пользователей:

   ```sql
   insert into public.wishlist_members (user_id)
   select id
   from auth.users
   where email in ('FIRST_EMAIL', 'SECOND_EMAIL')
   on conflict (user_id) do nothing;
   ```

   Убедись, что добавлены ровно два аккаунта:

   ```sql
   select count(*) from public.wishlist_members;
   ```

4. В **Authentication → URL Configuration** добавь адрес будущего сайта вида `https://USERNAME.github.io/REPOSITORY/` в Site URL и Redirect URLs.

Фотографии не нужно коммитить в GitHub. На главной нажми на приглашение поверх фотографии — откроется отдельный альбом. Можно выбрать сразу несколько снимков или целую папку `scripts\photos`; для каждого фото укажи дату. Имена исходных файлов содержат время экспорта, поэтому дата воспоминания задаётся вручную. На iPhone выбирай несколько снимков из медиатеки через кнопку «Выбрать фото». Размер оригинала — до 20 МБ; в списке показываются облегчённые превью, а оригинал загружается при открытии снимка.

Фотографии одного дня складываются в общий коллаж, а дата показывается под ним. Нажми на фото, чтобы открыть его крупно, листать кадры этой даты стрелками или клавишами, изменить дату или мысли, либо удалить снимок. Истории добавляются отдельно: на странице «Истории» нажми «Добавить историю», укажи название, дату и рассказ; фотографию можно прикрепить по желанию. Тема оформления переключается кнопкой с солнцем/луной и запоминается на этом устройстве. Альбом и истории доступны обоим участникам; при GitHub Pages данные сохраняются в общей базе Supabase и закрытом Storage.

### Настройка GitHub Pages

1. Загрузи проект в GitHub. GitHub Pages доступность для приватных репозиториев зависит от тарифа аккаунта; если тариф не поддерживает Pages для private-репозитория, для бесплатной публикации понадобится public-репозиторий. Исходники интерфейса в любом случае следует считать публичными.
2. В **Settings → Secrets and variables → Actions → Variables** добавь:
   - `SUPABASE_URL` — Project URL;
   - `SUPABASE_PUBLISHABLE_KEY` — Publishable key (или legacy anon key).

   Это публичные настройки для браузера, не секреты. **Никогда не указывай Secret key или `service_role`.** Сборка специально завершается ошибкой, если обнаружит секретный ключ вместо Publishable key.
3. В **Settings → Pages → Build and deployment** выбери **GitHub Actions**. Workflow `.github/workflows/pages.yml` соберёт только статическую версию из `static/` и опубликует её после push в `main`.
4. Дождись успешного запуска workflow и открой адрес Pages. Войди двумя созданными аккаунтами. Проверяй, что без входа данные недоступны, оба участника видят общий список, а любой другой пользователь получает отказ.

Тарифы и квоты GitHub/Supabase могут меняться; проверь актуальные условия до публикации. До успешной проверки Pages не удаляй локальную SQLite-базу и не отключай Python-запуск. При проблеме отключи Pages workflow и продолжай пользоваться локальным `python app.py`; миграция доступа не удаляет данные и Python backend продолжит пользоваться своей серверной ролью.

### Запуск сайта одним ярлыком Windows

Чтобы задать параметры в самом PowerShell-файле, из папки проекта один раз запустите установщик:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup_wishlist_shortcut.ps1
```

Первый запуск создаст файл `scripts\wishlist_credentials.ps1`. Открой его в Блокноте: адрес проекта уже заполнен, замени только `PASTE_SECRET_KEY_HERE` на **Secret key** или legacy `service_role` key (не Publishable/anon key). Сохрани файл и запусти команду установщика ещё раз. После проверки Supabase скрипт зашифрует ключ средствами Windows для текущего пользователя и автоматически очистит временный файл; он также исключён из Git. Создастся ярлык **«Наша карта желаний»** на рабочем столе. Для смены ключа снова отредактируй этот файл и запусти установщик; после обработки он опять очистится. Чтобы изменения вступили в силу, останови старый сервер на порту 8765 (`Ctrl+C`) и нажми ярлык.

### Распознавание голосовых через Edge Function (необязательно)

Edge Function отправляет короткое Telegram voice-сообщение в Gemini для распознавания и сборки текста напоминания. В локальном режиме записи до 5 МБ идут через функцию, а при ошибке используется локальный Whisper. Для публикации нужны Node.js, интернет, Gemini API key и Supabase CLI login:

```powershell
npx --yes supabase login
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\deploy_voice_function.ps1
```

После успешного входа CLI может хранить авторизацию не в файле `~\.supabase\access-token` (например, в системном хранилище учётных данных), поэтому проверку входа выполняет сам CLI при публикации. Скрипт запросит Gemini API key защищённым вводом, временно создаст закрытый файл секретов и удалит его после публикации. API key и секрет функции сохраняются только в Supabase; код не содержит ключей. Функция использует отдельный проверочный секрет, вычисляемый из уже сохранённого Supabase secret key. При смене Supabase ключа повторно запусти публикацию. В облачном режиме Telegram голосовые требуют опубликованную voice-функцию; локальный Whisper остаётся запасным вариантом только для локального бота.

## Telegram-бот (необязательно)

Создайте бота через `@BotFather`, узнайте свой числовой Telegram user ID у `@userinfobot`. Настройку нужно выполнить один раз: откройте PowerShell в папке проекта и запустите:

```powershell
python -m pip install -r requirements.txt
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\configure_telegram.ps1
```

Введи токен через защищённый запрос и свой числовой ID. Для добавления девушки повтори эту команду и введи её ID. Токен сохраняется зашифрованным средствами Windows только для настройки и публикации.

Чтобы сам бот работал в Supabase, а не на компьютере:

1. Выполни `npx --yes supabase login`, если CLI ещё не авторизован.
2. Если в `data\wishlist.sqlite3` остались данные, которых нет в Supabase, сначала выполни `python scripts\migrate_to_supabase.py`. Она переносит настройки, желания, фото и напоминания, не удаляя локальную базу. Совпадающие ID обновляются локальными значениями — не запускай её повторно, если в Supabase уже есть более свежие данные.
3. Запусти `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\deploy_telegram_bot.ps1`.
4. Подтверди запрашиваемые Supabase CLI изменения production. Скрипт создаёт закрытые таблицы сессий и обновлений, расписание напоминаний, секреты в Supabase Vault/Function Secrets, публикует Edge Function и устанавливает Telegram webhook. SQL дополняет схему и не удаляет желания или напоминания.
5. Каждый пользователь из allowlist должен один раз открыть [бота](https://t.me/loveibeautifulbot) и нажать **Start** — Telegram не разрешает боту первым начинать переписку.
6. Перезапусти сайт ярлыком **«Наша карта желаний»**. Локальный Telegram polling будет отключён; сайт продолжит работать с базой Supabase, а бот/напоминания будут работать независимо от компьютера.

Скрипт спросит смещение часового пояса в минутах (по умолчанию UTC+6). Чтобы добавить пользователя или изменить часовой пояс после публикации, обнови локальную настройку и повторно запусти `deploy_telegram_bot.ps1`. Токен бота и секреты webhook не записываются в исходники или Git. Токен находится в Function Secrets Supabase; отдельные секреты для cron и уведомлений о выполнении хранятся зашифрованно в Supabase Vault. Публичный webhook принимает только запросы с секретным заголовком; команды обрабатываются только от разрешённых ID в личном чате.

Локальная SQLite-база и личная фотография исключены из Git через `.gitignore`; не снимай эти исключения для публичного репозитория.

У бота есть кнопки **«Добавить желание»**, **«Напоминание»**, **«Мои желания»** и **«Помощь»**. Напоминание можно отправить так: `завтра 18:30 купить цветы`, `через 2 часа позвонить маме`, `12.11 09:00 забрать заказ` или командой `/remind завтра 18:30 купить цветы`. Уведомления о напоминаниях и о выполненном приключении приходят каждому добавленному пользователю; для этого девушка тоже должна нажать **Start** у бота.

Голосовые в облачном режиме требуют отдельного развёртывания `voice-reminder` и секрета Gemini. Если голосовая функция не настроена, бот попросит написать напоминание текстом.

Чтобы включить планируемое и фактическое время в уже настроенном Supabase, выполни в **SQL Editor**:

```sql
alter table public.wishes add column if not exists planned_time time;
alter table public.wishes add column if not exists completed_time time;
```

Это добавит два nullable-поля, не меняя существующие желания. В локальной SQLite новые поля создаются автоматически при старте.

Голосовые напоминания распознаются Supabase Edge Function через Gemini, если она настроена; локальный бот может использовать Whisper как запасной вариант. Облачный бот не зависит от включённого компьютера; чтобы распознавать в нём голосовые, предварительно опубликуй `voice-reminder` через описанный выше `deploy_voice_function.ps1`.

## Возможности

- Добавление и удаление идей, фильтры по статусу.
- Счётчики дней отношений и дней до дембеля (даты задаются кнопкой «Наши даты»).
- Планирование идеи на дату и время с уведомлением браузера, если сайт открыт и разрешение выдано; при отметке выполнения сайт сохраняет фактические дату и время и отправляет сообщение в Telegram.
- Отметка выполненного желания и прикрепление фото JPEG, PNG или WebP до 3 МБ.
- Адаптивный интерфейс для телефона и компьютера.

Сервер по умолчанию слушает только `127.0.0.1`: сайт предназначен для локального использования и не опубликован в интернете. Не публикуйте backend в интернете с service-role ключом без входа пользователей и серверной авторизации.
